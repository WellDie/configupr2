# Отчёт по практической работе №2

**Дисциплина:** Конфигурационное управление  
**Вариант:** 22  
**Язык реализации:** Java 17+

## Цель работы

Разработать CLI-инструмент для получения и визуализации графа зависимостей
пакета Rust в формате Cargo без использования готового менеджера пакетов
или сторонних Java-библиотек для извлечения зависимостей.

## Реализованные этапы

1. **Минимальный прототип и конфигурация.** Добавлен разбор аргументов
   `--package`, `--repository`, `--test`, `--repo-file`, `--output`.
   При запуске параметры выводятся в формате ключ-значение. Неверные и
   отсутствующие аргументы обрабатываются с сообщением об ошибке и кодом 2.
2. **Сбор данных.** В обычном режиме загружается `Cargo.toml`; прямые
   зависимости и ограничения версий выводятся в консоль. Для транзитивных
   узлов используются записи публичного sparse-индекса Cargo.
3. **Основные операции.** Граф строится итеративным BFS. Для прекращения
   повторного обхода используется множество посещённых узлов; циклические
   рёбра сохраняются в графе. Дополнительно реализован тестовый режим с
   файлом графа, где имена пакетов состоят из заглавных латинских букв.
4. **Дополнительные операции.** Реализован BFS по обращённым рёбрам для
   получения прямых и транзитивных обратных зависимостей.
5. **Визуализация.** Создаются PlantUML-описание `.puml` и изображение `.svg`.
   В проект добавлены примеры диаграмм для трёх пакетов тестового репозитория:
   A, D и G.

## Результаты тестирования

Запуск `./test.sh` завершился успешно: пройдено 27 автоматических проверок.
Проверены разбор Cargo manifest, параметры CLI и обработка ошибок, BFS,
циклические связи, обратные зависимости, ограничения SemVer, PlantUML и SVG.
Дополнительно проверена загрузка `Cargo.toml` по HTTP-ссылке на локальном
тестовом сервере.

## Сравнение с Cargo

Для проверки на реальном проекте следует выполнить в его каталоге:

```bash
cargo tree --manifest-path Cargo.toml --edges normal,build
```

Затем сравнить список узлов и рёбер с графом, созданным приложением.
Потенциальные расхождения связаны с тем, что Cargo использует `Cargo.lock`,
features, целевую платформу и полноценное разрешение конфликтов версий.
Реализация данной работы выбирает последнюю подходящую версию каждого
пакета по записи sparse-индекса; optional-зависимости не раскрываются,
target-specific-зависимости не фильтруются по платформе, а git/path-зависимости
не раскрываются транзитивно.

Фактический запуск `cargo tree` в среде подготовки проекта не выполнялся:
исполняемый файл Cargo в среде отсутствовал. Поэтому выше приведено описание
методики и причин возможных различий, а не вымышленные результаты измерения.

## Использованные лекции

- Лекция №1 — командная строка, разбор команд и обработка ошибок.
- Лекция №2 — метаданные пакетов, репозитории, зависимости и SemVer.
- Лекция №3 — конфигурационные языки; формат TOML в `Cargo.toml`.
- Лекция №4 — хранение этапов разработки в Git и оформление коммитов.
- Лекция №5 — рассмотрена; виртуализация не входит в требования варианта 22.
