# Cargo Dependency Visualizer (Java)

## Назначение

CLI-приложение строит ориентированный граф зависимостей Rust-пакета формата
Cargo. Ребро `A -> B` означает, что пакет `A` зависит от пакета `B`.
Готовые менеджеры пакетов и сторонние Java-библиотеки для получения зависимостей
не используются.

Проект реализует все пять этапов варианта №22 практической работы №2:

1. **Конфигурация.** Параметры задаются аргументами командной строки; при
   запуске выводится конфигурация в формате `ключ=значение`.
2. **Сбор данных.** Приложение загружает `Cargo.toml` указанного репозитория,
   извлекает прямые зависимости и выводит их с ограничениями версий.
3. **Основные операции.** Транзитивный граф строится итеративным BFS
   (очередь `ArrayDeque`), повторное раскрытие узлов предотвращается множеством
   `visited`; циклические ребра при этом сохраняются.
4. **Дополнительные операции.** Реализован вывод прямых и транзитивных
   обратных зависимостей выбранного пакета.
5. **Визуализация.** Формируется PlantUML-файл `.puml` и изображение графа
   в SVG. SVG создаётся собственным рендерером на Java без внешних библиотек.

## Запуск

### Windows

```bat
run.bat --package serde --repository https://github.com/serde-rs/serde --output output/serde.svg
```

### Linux / macOS

```bash
chmod +x run.sh
./run.sh --package serde --repository https://github.com/serde-rs/serde --output output/serde.svg
```

### Тестовый режим

В тестовом режиме URL не требуется. Вместо него передаётся файл с описанием
графа. Имена тестовых пакетов должны состоять из заглавных латинских букв,
цифр и символа `_`.

```bash
./run.sh --package A --test --repo-file test-repo/graph.txt \
  --output examples/A.svg --reverse
```

Формат файла:

```text
A: B, C
B: D
C: D, E
D: C
E: F
F: B
G: A, E
H:
```

Пустая правая часть означает отсутствие зависимостей. Строки, начинающиеся с
`#`, являются комментариями. Тестовый граф содержит несколько уровней,
общие зависимости, изолированный узел и цикл `C -> D -> C`.

## Параметры командной строки

- `--package NAME` или `-p NAME` — имя анализируемого пакета. Обязательный
  параметр.
- `--repository URL` или `-r URL` — HTTP(S)-ссылка на репозиторий либо прямую
  ссылку на `Cargo.toml`. Обязательна в обычном режиме.
- `--test` — включить режим тестового репозитория.
- `--repo-file PATH` — путь к текстовому файлу графа; обязателен с `--test`.
- `--output FILE.svg` или `-o FILE.svg` — имя SVG-файла. По умолчанию
  `dependency-graph.svg`. Рядом сохраняется файл с тем же именем и расширением
  `.puml`.
- `--reverse` — дополнительно вывести все прямые и транзитивные обратные
  зависимости выбранного пакета.
- `--help` или `-h` — показать справку.

Примеры обработки ошибок:

```bash
./run.sh --package A --repository not-a-url
./run.sh --package A --test --repo-file missing.txt
./run.sh --package A --test
./run.sh --unknown value
./run.sh --package A --test --repo-file test-repo/graph.txt --output graph.png
```

Приложение завершает работу с кодом `2` при ошибке параметров или файлов.

## Как собираются данные Cargo

1. Из указанного репозитория загружается `Cargo.toml`.
2. Парсер извлекает имя пакета, версию и записи из таблиц зависимостей.
   Учитываются обычные, build- и target-specific зависимости. `dev-dependencies`
   и зависимости с `optional = true` не раскрываются.
3. Для транзитивных зависимостей Java-клиент запрашивает записи напрямую из
   публичного sparse-индекса Cargo (`https://index.crates.io/`). По ограничению
   версии выбирается самая новая подходящая незапрещённая версия.
4. BFS раскрывает зависимости по уровням, сохраняя каждое ребро. Уже раскрытый
   узел второй раз в очередь не добавляется, поэтому циклы не приводят к
   бесконечному обходу.
5. Обратные зависимости строятся по обращённым рёбрам и также обходятся BFS.

Это учебная реализация сбора и анализа зависимостей, а не полная замена Cargo
Resolver. В частности, она не читает `Cargo.lock`, не выполняет полное
разрешение конфликтов версий и признаков Cargo; выбирает последнюю версию,
подходящую под ограничение каждой отдельной зависимости. Необязательные
зависимости исключены, если они не активированы явно; target-specific-зависимости
учитываются без фильтрации по целевой платформе. Git- и path-зависимости
показываются как `@unresolved` без обхода их собственных зависимостей.
Альтернативные реестры, workspace-root без собственного `[package]` и сложные
многострочные TOML-таблицы не поддерживаются. Для защиты от чрезмерно больших
графов установлен предел в 600 узлов.

## PlantUML и SVG

При каждом успешном запуске создаются два файла. Например, для `--output
output/serde.svg` будут сохранены:

- `output/serde.puml` — исходное описание диаграммы PlantUML;
- `output/serde.svg` — автономное SVG-изображение, построенное Java-рендерером.

Подготовлены три примера визуализации тестового репозитория:

- `examples/A.puml` и `examples/A.svg` — граф для пакета A;
- `examples/D.puml` и `examples/D.svg` — граф для пакета D;
- `examples/G.puml` и `examples/G.svg` — граф для пакета G.
